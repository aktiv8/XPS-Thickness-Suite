# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

**XPS Thickness Suite** (repo `aktiv8/XPS-Thickness-Suite`, renamed from `XPS-Thickness-Calculator`; local folder `C:\Users\david\Documents\XPS-Thickness-Suite`): one Tkinter window with a tab per overlayer-thickness method.

- **Calculator & simulation** (`app.py`; the calculation is Python standard library only): oxide/hydroxide/nitride thickness from peak areas of the **same core level** using the Strohmeier equation (B. R. Strohmeier, *Surf. Interface Anal.* 1990, 15, 51; HarwellXPS Tech Note #1: https://subsite.harwellxps.uk/wp-content/uploads/2018/02/HarwellXPS_TechNote_01.pdf), plus the simulated spectrum.
- **Thickogram** (`thickogram.py` maths, `thickogram_tab.py` GUI): Cumpson's method for an overlayer and a substrate from **different core levels** (P. J. Cumpson, *Surf. Interface Anal.* 2000, 29, 403), with the classic nomogram embedded. Integrated from the user's separate `aktiv8/Thickogram` repo, which stays untouched; `legacy/thickogram_v1_3.py` is its unmodified script. The tab can also apply a **Topofactor** (`topofactor.py`; A. G. Shard, J. Wang, S. J. Spencer, *Surf. Interface Anal.* 2009, 41, 541, DOI 10.1002/sia.3044) to correct for fibres and particles.
- **ARXPS (tilt series)** (`arxps.py` maths, `arxps_tab.py` GUI, `vamas.py` file I/O, `synthetic.py` test data): overlayer thickness from a VAMAS tilt series, from the slope of x against 1/cos θ, with the azimuth read from the file when it is there. See "ARXPS tab" below.
- `gui_common.py` holds the shared palette, `setup_style()` and `Tooltip` so `app.py` and the tab modules don't import each other.
- **Documentation** lives once, as Markdown + LaTeX in `docs/*.md` (rendered by GitHub and, with typeset equations, by `help_viewer.py` in the app's Method / References tab). `README.md` is only a landing page; `NOTICE` has the attribution. See "Documentation" below before editing any of it.

The repo is **public** (the user chose to leave it public although the code derived from Prof. Jong Wan Lee's GlowScript program has no known licence — hence the NOTICE). Don't remove the attribution.

## Things that aren't obvious from a skim

- The single- and mixed-layer equations from the tech note are one code path: overlayer N, λ and RSF are intensity-weighted averages over the active components. With one component and RSF = 1 it reduces exactly to Strohmeier's equation. RSFs cancel for same-core-level metal/oxide pairs, so they default to 1.0.
- N = atoms_per_formula × density / molar_mass (e.g. Cu₂O uses 2 atoms); only ratios matter, so units are arbitrary but must be consistent.
- Take-off angle θ is measured from the **surface** (90° = normal emission), per the tech note. The validity limit reported is ≈ 3× the overlayer IMFP.
- Several presets are taken from the original papers, and `tests/test_regression.py` pins them to published numbers (a failing test after a preset edit means the preset drifted from the paper):
  - **Al / Al₂O₃**: Strohmeier 1990 — IMFP 2.8/2.6 nm (Al Kα) and 2.4/2.2 nm (Mg Kα), θ from the **surface**, Nm/Nox = 1.5. The paper rounds the log coefficient to 1.4 (`d = 28 ln(1.4 Io/Im + 1)`); the app uses the exact value (≈1.393), so expect ≤0.4 Å differences. The 3.40 g/cm³ Al₂O₃ density is back-calculated to give Nm/Nox = 1.5 (the paper quotes ~1.3–1.5), not a measured density. Biesinger's Al spreadsheet uses the same inputs and is also reproduced to 0.1 Å.
  - **Cu oxides/hydroxide**: Biesinger 2017 — densities 8.96/6.00/6.31/3.37 g/cm³, IMFPs 1.54/1.77/1.76/2.19 nm. These IMFPs are for **Cu LMM Auger electrons (KE ≈ 918 eV)**, not Cu 2p3/2 (KE ≈ 554 eV), so the presets are keyed `... (LMM)`. The parallel `... (2p3/2)` presets (1.01/1.23/1.22/1.51 nm) are **computed** with `tpp2m_imfp_nm()` (Nv 11/28/17/25, band gaps 2.1/1.25/1.85 eV), not published; the same function reproduces Biesinger's three oxide IMFPs at 918 eV to 0.2%, but his Cu(0) 1.54 nm is ~6% above TPP-2M at 918 eV (it equals TPP-2M at ~1000 eV), so the 2p3/2 metal value may sit slightly low. Never mix the two sets — thickness scales ~linearly with the IMFPs (the 63/13/25 example gives 3.2 nm with LMM vs 2.2 nm with 2p3/2). His ~3.2 nm worked example (63% Cu₂O, 13% Cu(OH)₂, 25% metal) is reproduced only with intensity-weighted N and λ, which is what the app does (averaging the Nm/N ratios instead gives 3.4 nm). The HarwellXPS tech note's Cu numbers (8.93 g/cm³, CuO 6.39) differ by ~1–2%.
  - **W / WO₃**: Carlson & McGuire 1972/73 — 19.3 and 6.8 g/cm³ (WO₃ at 6.8, not the bulk 7.16), IMFP 1.28/2.63 nm, 45° take-off. Their eq. (5) is the same equation as Strohmeier's; the test round-trips it.
  - Strohmeier and Carlson & McGuire were read in full; of Biesinger 2017 only the thickness section and Table 6 were checked. The tech note's own 4.4 nm Al example comes from the tech note's spectrum, not from Strohmeier's paper, so it cannot be reproduced.
- Si, SiO₂, Si₃N₄, Ti, TiO₂: densities and band gaps come from the user's Thermo Avantage `Densities.txt` (Si 2.33/1.12 eV, SiO₂ 2.196/8.9, Si₃N₄ 3.44/4.65, Ti 4.54, TiO₂ 4.26/3.05); IMFPs are **computed** with `tpp2m_imfp_nm()` (Nv 4/16/32/4/16) at Al Kα, not published. The same file lists Al 2.6989 and Al₂O₃ 3.97 g/cm³ (sapphire), which would give Nm/Nox ≈ 1.29, but the Al presets deliberately stay on Strohmeier's 1.5 (Al₂O₃ 3.40 back-calculated). Ti/TiO₂ binding energies are typical literature values, not from the file.
- Band gaps live in `BAND_GAPS_EV` (value, source) and in each preset's `band_gap_ev` (0 = metal, None = unknown); only `tpp2m_imfp_nm()` uses them. **Policy set by the user: never overwrite an existing entry** — the Avantage values win over any other list (e.g. their pasted list had Si 1.11, Ge 0.66, GaAs 1.43, SiO₂ 9.0, all ignored; only InP 1.27, GaP 2.25, CdTe 1.44, PbS 0.37 were new, tagged unsourced). `tests/test_regression.py::BandGapTable` enforces this.
- Extra pairs (Mg/MgO, Ge/GeO₂, Zn/ZnO, Zr/ZrO₂, Hf/HfO₂, Sn/SnO₂, SiC→SiO₂, GaAs & GaP→Ga₂O₃, CdTe→TeO₂, plus InP/PbS below) were added at the user's request. Densities and gaps use the Avantage file where it has them (Mg, Ge, Sn, SiC, GaAs, ZnO, ZrO₂, HfO₂); the rest (Zn, Zr, Hf metals; MgO, GeO₂, SnO₂, Ga₂O₃, TeO₂; GaP, CdTe) are **my handbook values, not from the user's files**, and the oxide choices are judgement calls (GeO₂ 3.64 amorphous, TeO₂ 6.04 paratellurite). Valence-electron counts (`TPP2M_INPUTS`) count s/p (+ unfilled d) electrons with filled d shells as core (Cu stays 11 to match Biesinger). Sanity check: Nm/Nox equals the Pilling–Bedworth ratio for 1:1 oxides and matches published values.
- InP (In 3d5/2 → In₂O₃) and PbS (S 2p → PbSO₄) were added once the user supplied their densities (4.81, 7.60 g/cm³). In₂O₃ and PbSO₄ densities are handbook values and their band gaps (2.9, 4.5 eV) are rough estimates (`ROUGH` in `BAND_GAPS_EV`). The In 3d5/2 shift (~0.3–0.5 eV) is barely resolvable and InPO₄ (the other native-oxide component) is not modelled; PbS→PbSO₄ is clean because the S 2p sulfate shift is ~7.5 eV (Pb 4f cannot separate PbO well, so PbO is not modelled).
- Deliberately NOT added: ZnS (no clean oxide route), diamond/graphite (no meaningful oxide overlayer), As₂O₃ for GaAs (no band gap/density from the user), CdO for CdTe (Cd 3d can't resolve it).
- SiON is a rough placeholder, not sourced; the GUI makes all presets editable. Binding energies don't enter the thickness calculation, but they position the peaks in the simulated spectrum.

## GUI layout (`app.py`)

One window, two notebook tabs ("Calculator & simulation", "Method / References"). The first tab is a vertical `ttk.PanedWindow`: top pane = Inputs card (left) + Calculation card (right: primary button, big readout, validity badge, details box, Clear/Export buttons); bottom pane = Simulated spectrum. Styling lives in `setup_style()` (the `clam` theme, palette constants at the top of the GUI section, `Primary.TButton`, `Card.*` styles) plus a small `Tooltip` class. The window is sized from the screen in `_initial_geometry()` (≤ 1500×980, 93% of the screen height) and `self.compact` (window height < 880) switches to smaller fonts, tighter rows, no header/hint, the angle entry folded onto the Substrate row, and the button + readout sharing a row. `_place_sash()` sets the divider to the top pane's natural height.

Gotchas learned the hard way (all verified with screenshots, which is the only way to check this GUI): (1) bind the matplotlib canvas `<Configure>` with `add="+"` — a plain `bind` replaces matplotlib's own resize handler and the figure silently stops following the pane; (2) `NavigationToolbar2Tk` requests the full figure width, so `toolbar.configure(width=250)` is needed or it pushes everything sideways; (3) figure margins are computed in **pixels** from the live figure size and the figure is redrawn (debounced) on resize — fractional margins break on short panes; (4) a `ttk.Label` that wraps to its own width needs a small requested `width` or its unwrapped text squeezes its neighbours; (5) the Edit tool can't see Tk behaviour — drive the real window (`PIL.ImageGrab` of the window rect works on this machine) rather than guessing.

## Simulated spectrum pane (`spectrum_sim.py`)

Optional (numpy + matplotlib; `app.py` guards the import and sets `HAVE_PLOT`, and without them the pane just shows an install hint). `spectrum_sim.py` is pure numpy with no Tk, so it is unit-tested directly (`tests/test_spectrum_sim.py`); `app.py` only holds the Tk/matplotlib glue (`_build_spectrum_pane`, `_refresh_spectrum`, `_draw_spectrum`, fed by `self.last_calc` which `_on_calculate` fills).

- It is an **estimate, not a fit**, and every figure says so (`DISCLAIMER`). `oxide_area_fractions()` is the forward form of the Strohmeier equation and reuses the `N_ov_avg` / `lam_ov_avg` / `rsf_ov_avg` that `strohmeier_thickness()` returns, so simulating at the calculated d reproduces the entered area ratio exactly (tested). Intensities are relative (areas normalised to 100%).
- `CORE_LEVEL_MODEL` (spin-orbit splitting, branching ratio, default FWHM, Lorentzian mix) holds **typical literature values from general knowledge, not from the user's files**; FWHM is editable in the tab. The preset BE is taken as the lower-BE j-component (2p3/2, 3d5/2, 4f7/2) with the partner at +splitting. `model_for()` returns None for Auger presets (`Cu LMM`, `Zn LMM`), which are deliberately not simulated; a test enforces that every preset with a BE has a model and every Auger preset has none.
- Not modelled: shake-up satellites (CuO, Cu(OH)₂), asymmetric metal tails, plasmon/loss features, Auger lines. **The figure must say so** (user requirement): `ignored_features()` returns the note printed under the plot and, for Cu 2p with CuO/Cu(OH)₂, a hatched "Cu(II) shake-up satellite region (not simulated)" band; `CoreLevelModel.ignored_note` holds the per-level text (Cu 2p quotes Biesinger's main/satellite ratios 1.89 CuO, 1.57 Cu(OH)₂ ⇒ satellites ≈ 35–39% of the Cu(II) area, so the drawn Cu(II) main peak is overstated). Note for thickness inputs: with Cu 2p3/2 the Cu(II) area should include the satellite. The band position (main + 5.5 … + 11.5 eV, i.e. ~939–946 eV) is an approximation consistent with the satellite components scattered through Biesinger's Table 4 text (~940–945 eV); that table's layout is scrambled in the PDF text and the PDF can't be rendered here, so exact satellite BEs/areas were not read. Background is a self-consistent Shirley step (15% of peak height). The default window clips a little Lorentzian tail (≤ ~3% of area), which the tests allow for.
- A user spectrum is loaded as 2-column text/CSV (BE, intensity; headers skipped) and min–max scaled to the simulation height, so it is a shape comparison, not a quantitative overlay.

## Thickogram tab (`thickogram.py`, `thickogram_tab.py`)

`thickogram.py` is pure numpy/math (no Tk, no pyplot) so it is unit-tested directly (`tests/test_thickogram.py`); `thickogram_tab.py` is a `ttk.Frame` (Inputs + Calculation cards on the left, embedded nomogram on the right) that `App._build_thickogram_tab()` places in the notebook. `HAVE_THICKOGRAM` guards the import: without numpy/matplotlib the tab shows an install hint.

- Equation: `ln(A/2) − (B^0.75 − 0.5)x − ln sinh(x/2) = 0`, `x = t/(L cosθ)`, `A = Io/(Is·So/Ss)`, `B = KEo/KEs` with `KE = source − BE`. f is strictly decreasing from +∞ to −∞, so there is always exactly one root; `solve_x` brackets and bisects (relative tolerance, so tiny roots are precise) and raises `ValueError` for non-positive/non-finite A or B. **At B = 1 it is exactly `x = ln(1 + A)` = the Strohmeier equation** — a test cross-checks it against `strohmeier_thickness()`.
- **Angle convention differs from the Calculator**: Thickogram θ is from the surface *normal* (`cos`, 0 = normal emission); the Calculator's θ is from the *surface* (`sin`, 90 = normal). Convert with `normal_from_surface` / `surface_from_normal`; the tab shows the live conversion and "Copy from Calculator" applies it. Never mix them silently.
- The original script's "redline plots correctly" to-do was a real bug: the red line must run from `(0, ln(A/2))` to `X = 2·x_B` (`x_B = (4.2 − B)/0.6`), not to the thickness position; `solution_line()` has the fix and a test checks that the line meets the green curve at `X = 2x`. The nomogram constants (`AYP`, `AXD`, `BX`, 4.2, 0.6) and drawing code are kept verbatim from the original.
- Parity with the original is tested with golden `(A, B, x)` values produced by the original, unmodified solver (`GOLDEN` in the test file). `legacy/thickogram_v1_3.py` is pinned with `.gitattributes` (`-text`) so git does not normalise its CRLF line endings — keep it byte-identical to the original in `aktiv8/Thickogram`.
- Presets only prefill binding energy (+ λ for the overlayer); presets carry no real RSFs, so So/Ss and the peak areas are always typed. `Copy from Calculator` does not copy areas (the Calculator's areas are same-core-level components, a different meaning).
- The matplotlib lessons in "GUI layout" above (bind `<Configure>` with `add="+"`, toolbar width, redraw on resize) apply here too; the nomogram has no ticks so fractional figure margins are fine.
- `tests/test_gui_smoke.py` builds the real window and drives this tab; it skips itself when there is no display.

### Topofactors (`topofactor.py`, sample-shape controls in the tab)

`TF = T/t`: the planar Thickogram thickness `t` times the Topofactor gives the true conformal thickness `T` of a coating on a fibre or particle (paper: Shard, Wang & Spencer 2009, read in full from the user's PDF). Pure Python (math only); `apply_topofactor(result, shape, mode)` consumes a `ThickogramResult`. The tab keeps the planar solution and re-applies the factor when the shape/mode changes (`_present()`), so changing the shape never re-solves.

- Regimes (`topofactor()`): `t/L < 0.1` thin-film limit (cylinder 2/π, sphere 0.50, shadowed sphere 0.57); `0.1 ≤ t/L ≤ 3` Eq. (6) `TF = c0 + (c1 + c2 ln B) t^k + c3 exp(−c4 B)` with the paper's Table 1; above 3 the value at 3 is held with a warning. `mode="constant"` uses the paper's averages 0.79 / 0.67 / 0.71. The factor jumps slightly at 0.1 where the limit meets Eq. 6 (documented, tested).
- **Units trap:** the paper's `B` is `(Eo/Es)^0.75`, but `thickogram.py`'s `b` is the plain kinetic-energy ratio (it applies `^0.75` inside). Always go through `topofactor.b_paper(b)`. A test reproduces the paper's own experimental values (1.19 for C 1s:O 1s, 0.90 for C 1s:Si 2p). `t` in Eq. (6) is `t_nm / L`, not nm.
- The paper's Table 1 caption says "Eqn (7)" but the parameters are for Eqn (6); its sphere value 0.67 is quoted at t = 1.5 in the text but at T = 1.5 in Table 2 (Eq. 6 gives 0.66 at t = 1.5). Both are noted in `docs/methods.md`.
- Conditions the tab warns about: θ ≠ 0 (mean normal must face the analyser) and B outside 0.7–1.4 (Eq. 6 is best near 1). It always notes that Topofactors do **not** apply to nanoparticles/nanofibres — the paper's separate nanoscale model (its Eqs. 7–9) is deliberately **not** implemented: its exponents are scrambled in the PDF text layer and the page could not be rendered here, so it can't be transcribed reliably. Eq. 10 of the paper defines `Ro = Xo So / (Xs Ss)` (atomic fractions), which the docs and tab hints now say; the tab still takes So/Ss as typed values.
- Topofactors are applied on the Thickogram tab only (user decision); the Calculator tab's Strohmeier result is a planar-film result.

## ARXPS tab (`arxps.py`, `arxps_tab.py`, `vamas.py`, `synthetic.py`)

User request: angle-resolved thickness from a tilt series (intensity against 1/cos θ) plus azimuth, loading VAMAS from a Thermo K-Alpha+ (sample data in `C:\Users\david\Documents\Working Directory\20250626\Dave Morgan\X-Ray014 400um - FG  ON`, Si and GaAs wafer tilt series). Decisions: windows + Shirley (no peak fitting), the ratio method only (no substrate-only ln I), azimuth read when present. **The user's files are not in the repo** (public repo, their data): tests and docs use `synthetic.py`; `tests/test_vamas.py` has real-file tests that skip when the folder is absent.

- **One engine for both modes.** Per angle `x_i = d/(λ cos θ_i)`: mode 1 (two states of one peak) `x = ln(1 + R/R∞)` with `R∞ = (S N λ)ov/(S N λ)sub` built from the Calculator presets; mode 2 (different peaks) `x = thickogram.solve_x(A, B)`. Mode 1 is the `B = 1` case; tests check both against `app.strohmeier_thickness` and `thickogram.thickness` per angle. `x_i = k u_i`, so x against `u = 1/cos θ` is a line through the origin; `d = kλ`; the free-intercept fit is the diagnostic; the R∞-free fit (mode 1) reports `edge=True` when the data cannot determine R∞ (real data are often too linear in u) — shown in the details, not as a badge warning. Angles are from the surface **normal** (as the Thickogram tab), emission angle = tilt + offset; angles above `max_angle` (70°) are drawn but not fitted.
- **VAMAS quirks** (`vamas.py`; learned by parsing the real files): `1e37` = unspecified; the per-block value count `n` is the **total** across the interleaved corresponding variables (Counts, Transmission), so points = n/2; the K-Alpha tilt sits in experimental variable 1 whose label is only "Exp Variable 1" (unit `d`), azimuth (variable 2) and the sample-normal fields are `1e37` in the supplied files; KE axis, `BE = hv − KE` (no work function); counts are **raw sums over scans** (noise = √counts), so `intensity()` divides by scans × dwell (matters across regions with different scan counts, e.g. Ga 3d has 6) and by the Transmission column. Only NORM/REGULAR/XPS is read (`VamasError` otherwise). Python 3.14's numpy has no `np.trapz`: use `np.trapezoid` (code falls back).
- **Alignment is shape cross-correlation, sequential** (`xcorr_shift`, each spectrum matched to the previous aligned one). Earlier tries failed on real data: peak-maximum alignment breaks when the oxide peak is taller than the substrate (GaAs Ga 3d oxide), and matching every spectrum to the 0° one is biased when composition changes a lot. Auto-detected windows (`auto_two_state_windows`) identify the substrate state as where the normalised spectrum **falls** with angle and the overlayer state where it **rises**, not "the tallest peak". The split is the valley, or the midpoint if there is none. A shared Shirley background covers the whole envelope for two-state data.
- **Known limit, warned in the code:** states closer than 2 eV (GaAs oxide/substrate ~1.3 eV) cannot be separated by a window split (`MIN_STATE_SEPARATION_EV`); the result is only rough and peak fitting would be needed (out of scope, deliberately). Merged peaks also make auto-detect refuse ("Could not tell the two states apart") rather than guess. On the real Si wafer the result (~1.7 nm) is sensitive to the split position (1.4–2.0 nm for splits 101.8–100.0 eV) and the free-intercept fit does not pass through the origin (intercept ≈ +0.19), which the badge reports honestly; do not "fix" that by tuning.
- The tab is a ttk notebook of three setup pages (Data, Materials, Windows) on the left because the inputs do not fit a 691 px laptop otherwise, and a notebook of three matplotlib pages (Spectra, x vs 1/cos θ, Azimuth) plus a Treeview table on the right. Multi-azimuth files: each azimuth is aligned to the first azimuth's lowest-angle spectrum and fitted separately; the headline is the azimuth mean. `tests/test_gui_smoke.py::ARXPSTabSmoke` drives it with synthetic files.
- **Areas from a CasaXPS fit** (`casa.py`, `arxps.analyse_fitted_states/peaks`): a second area source next to windows, chosen automatically when the region's blocks carry `CASA region/comp` comment lines. `casa.py` is a trimmed **port of eXPoSe's parser** (`C:\Users\david\Documents\Mutli-Data-Browser`: `casafit.parse/calibration/component_be`, `quant.state_of`; the user's own project, no licence file, credited in `NOTICE`). **Deliberately not ported:** `lineshapes.py` (its tables come from an analysis of CasaXPS.exe; the user chose parser-only for the public repo), `curves()` and the CSV/sidecar import, so the Spectra page marks the stored component positions and does not redraw peak shapes. Facts that matter: stored `Area` is counts/s·eV and **raw** (not transmission-corrected), used as it is; positions are **KE** in the stored frame (`BE = hv − pos − comp_shift + calib_shift`; a `Calib M= A=` line moves displayed BEs, never areas); a **state** = components sharing `INDEX >= 0` (doublet partners add up; a partner stores `RSF 0`, so never use component RSFs), else a component on its own; a block may hold several fit regions (Ga 3d + As 3d), chosen on the Components page. `auto_roles` calls a state substrate if its share of the fitted area **falls** with angle and overlayer if it **rises** (±0.02), so it works when the oxide is the bigger state; every row is editable. Mode 2 applies the block's Transmission column at each component's KE (stored areas are raw) and prefills So/Ss and the BEs from the fit. On the user's `Fitted Si tilt.vms` (beside it `Si.csv`, a CasaXPS export whose areas equal the stored ones): `Si 2p El`/`Si 2p Ox`, d = 1.72 nm, versus 1.73 nm from windows. `docs/sample/si-native-oxide-arxps-fitted.vms` is the synthetic equivalent (a test regenerates both samples and compares bytes; `.gitattributes` pins them `-text`).
- The R∞-free fit now reports "not determined" (`edge=True`) also when `k·u_max < 0.5` (the exponential is nearly linear over the angles, so R∞ and k are interchangeable); the CasaXPS-fitted real data triggered that.
- Synthetic recovery accuracy (noise-free, Gaussian peaks, 4 eV apart): 1.498 nm for 1.5; with noise and 20% Lorentzian tails ~1.48. Tests use tolerances accordingly.

## Depth profile tab (`depthprofile.py`, `depth_tab.py`)

User request: add the ARCtick features not yet covered, starting with the **Surrey Trend Plot**, then Stratification (Type II), Gries layers (Type III) and Regularisation (Type IV) plus attenuation-length helpers (plan approved in four phases, one commit each). ARCtick = P. Cumpson's NPL spreadsheet; the user's HTML conversion is `D:\Cloud Services\OneDrive - Cardiff University\Claude Projects\ARCTick\arctick_harwellxps.html` (private repo `aktiv8/HarwellXPS-ARCTick`). **Licence trap:** that page says ARCtick is not to be copied without NPL's permission, and the Suite is public, so everything here is an **independent implementation from the published physics** (Cumpson 1995, Gries 1989...): no code, text or images copied, no "ARCtick" in tab titles, credited in `NOTICE`. The HTML is also only a simplified reimplementation (placeholder uncertainties, no non-negativity, Gries ignores attenuation through other layers), so treat it as a spec of the user-facing methods, not as ground truth.

- **Species** (`depthprofile.Species`): a CasaXPS fitted state (`species_from_fits`, from `arxps.read_fits`, areas as stored, per-component transmission) or a whole region (`species_from_region`, Shirley over `auto_envelope`, i.e. only the stretch where the smoothed spectrum stays above 10% of its range, +1.5 eV). Counting-noise sigma per area = `step·sqrt(sum counts)/(scans·dwell)` (`area_sigma`). Default lambda = TPP-2M for an oxide-like matrix (`app.tpp2m_imfp_nm(ke, 2.196, 60.08, 16, 8.9)`), only a starting guess. The Seah-Dench IMFP formula could not be verified from a source here, so it is **not** used; verify before adding.
- **Trend plot:** `ln I = ln I(0) − (z/λ) sec θ` per species; `trend_fit` (OLS in sec θ, max-angle rule), `trend_table` (slope, se, rms scatter, apparent depth `−λ·slope`, "parallel to" = slope difference < 2·combined se and KE ratio within 0.7-1.4). An overlayer-type species curves (1 − e^−x); a thin buried layer is exactly straight.
- **Shirley was made robust** because whole-region Si 2p exposed it: the fixed-point iteration diverges when the high-BE end is high (long loss tail) and returned negative/huge areas. `arxps.shirley_info` falls back to solving the step rate directly (dB/dE = κ(y−B), implicit trapezoid, root-find on κ), rejects a solution that swallows the peak, and otherwise uses a straight line (`ok=False`). Where the classic iteration converges the result is identical (tested).
- **Stratification (phase 2):** thin layer `I = S n exp(−z sec θ/λ)` → `z = −λ ln R/(sec_b − sec_a)`, `n = I_a exp(z sec_a/λ)/S` (the HTML ignored the attenuation correction and drew no bar widths); pair mode (default a = smallest angle, b = nearest 67.5° within the max angle, ties go to the lower) or all-angle fit; σ_z from counting statistics; `curvature_t` (t of the quadratic term in ln I vs sec θ) warns for multi-layer species. A finite overlayer *rises* with angle → negative depth + note; a bulk substrate is reported at its information depth and usually trips the curvature warning (both expected, documented). **Geometry option** (`apply_geometry`, divide by cos θ): on the user's K-Alpha tilt series every species, substrate included, falls roughly as cos θ faster than depth explains (O 1s lands at 2.6 nm, outside a 1.7 nm oxide; 0.6 nm with the correction), so the tab offers it explicitly; default is none (X-ray-spot-defined area, as ARCtick assumes). Ratios on the ARXPS tab never need it.
- **Layers / Gries (phase 3, `depthlayers.py`):** forward model with attenuation through every layer above (the HTML ignored that), curves normalised to their own first angle (no RSFs), `gries_chi2`, own bounded Nelder-Mead (`nelder_mead`, with restarts because clipping flattens the simplex against a bound), `fit_layers` (multi-start), `scan_ranges` (profile χ² per layer, others re-fitted, Δχ² = 1 scaled by reduced χ²; with noise the deep layer's range is wide, as it should be), `default_assignment` (rank by stratification depth, deepest = substrate). `default_layout` also puts a plain C 1s region (`is_adventitious_carbon`) in layer 1 regardless of its depth rank: on the user's Si wafer carbon ranks deeper than the oxide (U-shaped, rises less than Ox against sec theta), which is a ranking artefact, not physics. One species = one layer; one λ per species in all layers (a limitation). **It does NOT fit the user's real K-Alpha Si wafer** (C 1s + Si 2p Ox + Si 2p El stack: χ²/pt ≈ 2000, thicknesses run to bounds, even with a free geometry exponent): a common tilt factor that is not a power of cos θ, a carbon layer that is not a clean layer, etc. Do not "fix" that by tuning; the docs say so and point to the ARXPS ratio method. Source option "Fits where available, else regions" is the default (`SRC_AUTO`). Gries 1989 DOI 10.1116/1.576066 verified via Crossref. Test data: `synthetic.layered_series` (exact layer-model intensities, Gaussian peaks).
- **Default Layers assignment (`depthlayers.default_layout`):** the user asked why Si 2s (not Si 2p) became the substrate on their Si files. Old rule = deepest average depth → Si 2s (5.9 nm) beat Si 2p El (5.5 nm); a semi-infinite substrate has no single depth and a whole-region Si 2s mixes substrate and oxide (curvature t ≈ 12). Now: the substrate is the **fitted state whose share of its region's fitted area falls most with angle** (fallback: deepest when there are no fits); whole-region species with |curvature t| > 5 are left out (unticked, with a note) when the substrate came from fits; the rest are ranked by depth. Note that without the geometry correction C 1s ranks *deeper* than the oxide on the user's data (4.3 vs 2.6 nm), so it is not layer 1: that is the stratification depth ordering, not a bug.
- **Regularised profile (phase 4, `depthreg.py`):** per species `I/S = Σ c_n A_mn` (slab integrals of exp(−z/λcosθ), same as the HTML) with Tikhonov second-difference smoothing, weights from counting noise, own Lawson-Hanson `nnls`, bulk `constant`/`zero` below a depth by merging/dropping deep slabs, covariance bands `G Gᵀ` (noise only, NOT smoothing bias; the docs and tab say so), "atomic fraction" is display-only normalisation (no joint closure constraint). **Alpha selection lesson:** GCV badly under-smooths with only ~6 angles (χ²_red 0.09, wild oscillations); the default is the discrepancy principle (smoothest profile with misfit ≤ n); GCV stays available. A first patch that replaced `choose_alpha` by slicing the file duplicated code: when rewriting functions in a file, rewrite the file or edit exactly. **AL helpers:** only a verifiable one is built, an "AL / IMFP" factor (default 1.0; Cumpson & Seah 1997 say AL is 10-30% below IMFP) scaling the TPP-2M starting lambdas; the Seah-Dench IMFP and the Cumpson-Seah AL formula could not be verified from a source, so they are not implemented (verify before adding). Validity guidance (≈60-70°, diffraction, roughness) is in the docs only.
